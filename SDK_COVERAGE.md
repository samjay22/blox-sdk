Source audit: 2026-11-12. Generated by `tools/gen.py` from the reviewed controller/DTO inventory in `spec/endpoints.json`; `tools/check-coverage` independently scans available controllers. `routes.json` is the exact exposed SDK route set. Gateway: `https://lb1.blox-api.com`.

## Scope and evidence

- Fields, Leaderboard, Platform and Audit: local `~/work/svc/*-service` controllers, DTOs, API contracts where present, security and scope checks. Auth, Matchmaking and Codes: `~/work/srv/src-gas`, `src-mm`, `src-roblox-code-service`.
- The additional batch changes route (378 total routes) implements the explicit shared contract in `docs/PROFILE-SYNC-CONTRACT.md`, not an independently verified deployed controller. Backend deployment support remains unverified.
- Four session/commit routes implement the binding `../scale/CONTRACT.md` v1 wire contract in `API_CONTRACT.md`; parallel backend support is not live-verified.
- Party: neither `~/work/srv/src-CrossServerPartyService` nor `~/build/src-CrossServerPartyService` is present. Its 16 checked-in methods are retained, but **current Party controller/DTO parity is unverified**. No remote server access was attempted.
- Every machine-key-relevant endpoint discovered in the available sources has an SDK method. Identity/portal methods retained by the SDK are labeled; their existence is not permission for a machine key to use them. Server-enforced universe/org grants remain authoritative.
- Dynamic game configuration is ConfigService (`client.configs`): namespaces of JSON values under the client universe, curated from `~/work/svc/config-service/docs/API.md`. Fields is player data only: no UNIVERSE scope, game values, subject 0 or SET_CONFIG schedule action. No compatibility alias or fallback is provided.
- Platform currently exposes metering, plans, rate limits, webhooks, analytics and developer tools. No LiveOps, environment promotion, flag or exposure controllers exist in its current `src/main/java`. Removed speculative SDK methods are not aliases. Use Fields schedules, environments and flags where exposed; missing Platform capabilities are service-side work, not SDK coverage.
- SDK 3.0 uses internal operation paths without gateway prefixes; no direct-host routing or fallback is supported.
- Offline verification is not proof of gateway rewrites, deployed backend parity, production key grants or native Roblox networking. No live HTTP calls were made.

## Intentional framework/operational exclusions

These framework patterns are not gameplay functionality. Exact enabled actuator endpoints depend on the checked-in Spring management configuration; named probe controllers, health, metrics and info wrappers are inventoried above when present. No generic URL escape hatch is added.

| HTTP endpoint / pattern | SDK mapping / reason |
|---|---|
| `OPTIONS /**` (CORS-enabled services) | intentionally not in SDK: portal/admin-only; browser preflight, not a Roblox server operation |
| `GET /metrics/{requiredMetricName}` (root-base actuator services) | intentionally not in SDK: portal/admin-only; operational Micrometer inspection, including optional `tag` selectors |
| `GET /health/{*path}` (root-base actuator services) | intentionally not in SDK: portal/admin-only; dependency/component diagnostics; use named health/probe methods for coarse checks |
| `GET /actuator/health` and `GET /actuator/health/{*path}` (default-base actuator services) | intentionally not in SDK: portal/admin-only; deployment diagnostics, not game-server state |

No portal/admin-only domain endpoint is omitted from the current SDK inventory. Party is an evidence gap, not a verified omission or verified completion.
